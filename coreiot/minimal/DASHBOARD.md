# Minimal CoreIOT dashboard

Use the existing `Smart Classroom` profile and `classroom-01-sim` device in the course tenant. The device alias points to the device entity and works independently of its profile name. Follow the [platform deployment guide](../docs/PLATFORM_DEPLOYMENT.md) for device and simulator setup.

## Import and bind the dashboard

1. Open the already imported humidity dashboard. For a fresh dashboard, use **Dashboards → Add dashboard → Import dashboard** with the [humidity dashboard](smart-classroom-humidity.dashboard.json). Use the [temperature and humidity variant](smart-classroom-temp-humidity.dashboard.json) on hardware only when the sensor supplies temperature. Name the sandbox dashboard **Smart Classroom — Synthetic**. A separate dashboard for synthetic temperature can use **Smart Classroom — Synthetic Temperature**.
2. Switch to **Edit** mode, open **Entity aliases** in the toolbar, and click the pencil beside **Classroom**. Set **Filter type** to **Entity name**, **Type** to **Device**, and **Name expression** (the Entity name filter) to `classroom-01-sim`. Turn **Resolve as multiple entities** off. Save the alias, save the **Entity aliases** dialog, then save the dashboard. This filter matches a name prefix. If any other entity shares that prefix, use **Single entity** as the filter type, select **Device**, and select the exact `classroom-01-sim` entry. Use **Single entity** for the hardware dashboard as well. [Entity filter fields in v4.2](https://github.com/thingsboard/thingsboard/blob/v4.2/ui-ngx/src/app/modules/home/components/entity/entity-filter.component.html) · [Alias behavior](https://thingsboard.io/docs/pe/user-guide/aliases/#alias-types)
3. In view mode, check that **Device status → Device** shows `classroom-01-sim`. Compare it with the `deviceId` value under the device's **Latest telemetry** tab before using either control. If widgets are empty, confirm that the alias resolved and that **Latest telemetry** receives data. A dashboard imported from the repository starts with a placeholder filter and requires binding.
4. Verify **Last reported readings** (named **Latest readings** in the original import), **Humidity history** and **Recent humidity (30 s)**. The recent chart is an independent real-time window. An empty recent chart means no humidity point is currently in that window. Copy the latest UTC humidity timestamp from **Device status** when recording freshness. The **Last report (UTC)** column follows `deviceId` and may advance during a missing-humidity sample. CoreIOT activity follows the tenant's cloud inactivity policy and can remain active while the PC gateway has no recent board readings.
5. With LED automation disabled, open the browser developer tools **Network** tab and filter to `/api/rpc/twoway/`. Record the current `lamp` timestamp, then press **LED ON**. The request is `setLamp` with Boolean `true`, a 10-second timeout and persistence disabled. Check the response body for a correlated application ACK with `ok: true` and `actualState: true`. Verify **Board LED (last reported)** shows **On** and **Last LED report (UTC)** is newer than the baseline and current within 30 seconds. Repeat for **LED OFF** with Boolean `false`, matching ACK and a fresh **Off** report. The stock RPC Button displays transport errors and timeouts, and its success handler discards the response body. Capture only the request path and sanitized response or use correlated application logs. [v4.2 RPC Button implementation](https://github.com/thingsboard/thingsboard/blob/v4.2/application/src/main/data/json/system/widget_types/rpc_button.json)
6. Check **Active alarms** during the [humidity RuleChain](AUTOMATION.md) test. It lists active alarm objects for **Classroom** created in the last 30 days. Use the device **Alarms** tab to confirm clearing under the original alarm ID, and expand the widget window if an active alarm was created earlier.

Bind a separate dashboard to the physical `classroom-01` entity. Keep the controls removed there until Member A verifies the firmware's controllable board LED and Boolean `setLamp` support. Omit unsupported sensor keys and use the humidity-only variant when temperature is unavailable.

## Connect gateway AI events

The **Gateway AI events** time-series table uses the classroom alias and `aiEvent` as a proposed event key. The existing protocol has no agreed AI event payload. When Member B provides the actual mapping, edit the table's keys to match the gateway and change its alias if events are published under a different device. Confirm a genuine event appears with the same timestamp as the gateway log. The simulator leaves the event table empty.

## Verify tenant compatibility

The public CoreIOT OpenAPI reports `4.2.0PE`. The supplied configurations use v4.2's built-in Entities table, Time series chart, Alarms table, Time series table, and RPC Button. Run `node --test tests/coreiot/minimal-dashboard.test.cjs` from the repository root for offline checks. Verify the signed-in tenant's version, bindings, chart data, alarm filter and RPC responses after import. If a widget type differs, add the equivalent from the tenant's widget library with the bindings above and export the verified dashboard. [CoreIOT OpenAPI](https://app.coreiot.io/v3/api-docs) · [CoreIOT dashboard guide](https://coreiot.io/knowledge-base/tong-quan-ve-dashboard/)
